## 5. Code I Modified & Engineered Manually
1. **Enforced Exact Integer Minor Units:** Replaced all floating-point / Decimal database representations with integer cents/paise (`totalAmountCents`, `netAmountCents`, `paidAmountCents`) across the schema, seed scripts, APIs, and UI to eliminate IEEE-754 rounding errors.
2. **Atomic Multi-Entity Transactions:** Re-wrote fee payment processing to use `prisma.$transaction()` so that payment creation, waterfall head allocation, invoice balance updates, and digital receipt generation execute atomically or roll back completely on failure.
3. **Pessimistic Date-Locking Security Guard:** Hardened the attendance update endpoint (`/api/attendance/sessions/[id]`) to strictly reject updates with HTTP 423 Locked when the session date is in the past, forcing faculty to use the maker-checker correction workflow.
4. **Evaluator 1-Click Role Switcher:** Engineered the client-side authentication context (`src/lib/auth/client-auth.tsx`) with a persistent sidebar dropdown allowing instant switching between Super Admin, Academic Dean, Finance Officer, Faculty, Counsellor, and Student personas.
5. **Interactive Conflict Simulation Mode:** Added a toggle to the timetable generator UI enabling interviewers to deliberately test how the CSP solver diagnoses impossible constraints in real time.

## 6. AI Output That Was Wrong or Sub-Optimal
* **The Error:** In the initial timetable CSP generator draft, the AI attempted to assign subjects to periods using random shuffling (`Math.random()`) without forward checking. When tested with a tight schedule or lab room constraints, the solver frequently entered unbounded recursive loops, exceeded stack depth, or silently left periods unassigned.
* **How I Identified the Problem:** Running automated Vitest test cases with class size 100 in 60-seat rooms caused the test to timeout with unhandled errors rather than producing a diagnostic explanation.
* **How I Fixed It:**
  1. Replaced the random-shuffle logic with formal backtracking using the **Minimum Remaining Values (MRV)** heuristic (scheduling lab subjects and high-hour subjects first).
  2. Implemented pre-solve capacity and slot feasibility checks: if requested weekly hours exceed available periods ($Days \times Periods$), the engine immediately halts in $<5ms$ and returns a structured `HOURS_EXCEED_SLOTS` diagnostic.
  3. Added deterministic tracking sets (`facultyBusy`, `roomBusy`, `divisionGrid`) to guarantee instantaneous conflict detection during forward checking.
