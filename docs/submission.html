2 Deep-Dive Engineering Highlights by Module

Module 1 • Statutory Compliance Assignment 1

Smart Attendance Management & Date-Locking

  • Hard 23:59 Date Locking: Sessions automatically lock at midnight of the session date. Direct faculty updates are rejected at the API layer with HTTP 423 Locked to eliminate backdated grade and attendance tampering.
  • Maker-Checker Correction Workflow: For legitimate waivers (official sports duty/hackathons), faculty submit a structured justification. Only the Academic Dean can review and atomically approve the update.
  • Statutory <75% Recovery Target Formula: Computes the exact consecutive classes needed to regain exam eligibility: Classes Needed = max(0, ceil(3*Sessions - 4*Attended)).
Module 2 • Financial Precision Assignment 2

Fee Collection & 3-Way Bank Reconciliation

  • Strict Integer Minor Units (Zero Float Drift): All financial arithmetic is computed in integer cents/paise (e.g. $5,850 = 585000 cents). Banning floating-point arithmetic eliminates fractional penny drift across multi-head ledgers.
  • Idempotent Checkouts: Unique database index on idempotencyKey guarantees that double-clicks or mobile network reconnects will never charge a parent twice.
  • Waterfall Partial Allocation: Payments automatically settle priority heads first (Tuition → Exam → Lab → Library).
  • Algorithmic 3-Way Bank Statement Matcher: Ingests settlement CSVs and executes 4 passes in O(N) time: exact matches, intermediary wire deduction flags ($15 wire charge detected), unrecognized direct deposits, and missing settlements.
  • Maker-Checker Refunds: Reversals require staff initiation and independent Finance Director authorization.
Module 3 • Pure Algorithmic CSP Assignment 3

Intelligent Timetable Generator (CSP Solver)

  • Backtracking with MRV & Forward Checking: Solves scheduling without clashing. Uses the Minimum Remaining Values (MRV) heuristic—placing scarce lab rooms and high-hour core subjects first.
  • Hard Collision Constraints: Enforces zero professor double-booking, zero room double-booking, room capacity ≥ class size, and lab subjects restricted exclusively to LAB type rooms.
  • Diagnostic Explainer on Impossible Constraints: If impossible requirements are entered (e.g., 24 hours in 20 periods, or 120 students in 80-seat rooms), the engine halts in <10ms and outputs structured conflict diagnostics explaining the bottleneck and remediation steps.
Module 4 • Operational SLA Assignment 4

Student Support & SLA Grievance Helpdesk

  • Departmental Auto-Routing: Routes tickets across Fees, Academics, Hostel, and Exams with category-specific SLA deadlines.
  • Live Urgency Countdown Timers: Dynamic indicators update remaining hours in real-time, transitioning urgency states (NORMAL → HIGH → CRITICAL → BREACHED).
  • 1-Click Managerial Escalation: Breached tickets can be escalated directly to the Director/Dean with automatic audit logging.
Module 5 • Conversion Pipeline Assignment 5

Admission Lead Management CRM

  • Weighted Round-Robin Assignment: Routes inbound leads (Web, Walk-in, WhatsApp, Education Fairs) by first matching certified course specialists, and second balancing active caseloads to prevent lead hoarding.
  • Ageing Radar: Highlights leads with past scheduled follow-ups and displays exact hours overdue.
  • Conversion Funnel Analytics: Tracks lead progression across New → Contacted → Campus Visit → Applied → Enrolled.

3 Technical Approach, Assumptions & Architectural Trade-offs

Architectural Decision Alternative Considered Why My Choice Is Superior for Higher Ed
Next.js 15 Full-Stack (Modular Monolith) Decoupled Microservices For a 5,000-student college, microservices add distributed transaction latency (2PC/Sagas) and high operational overhead. Next.js 15 with co-located REST endpoints and shared TypeScript contracts provides single-repo atomic consistency.
Integer Minor Currency (Cents/Paise) Float / Decimal IEEE-754 floating point arithmetic introduces rounding errors that compound in multi-head ledgers. Storing values in integer cents guarantees zero drift during fee calculation and bank reconciliation.
Deterministic CSP Backtracking with MRV Genetic Algorithms (GA) Genetic algorithms are non-deterministic, can produce subtle conflicts, and fail silently when constraints are impossible. A formal CSP solver either finds a zero-collision schedule or halts in <10ms with diagnostic proof of why it's impossible.
Pessimistic 23:59 Date-Locking Lax Grace Periods Regulatory bodies (UGC/AICTE/Accreditation boards) fail institutions that allow post-facto attendance manipulation. Hard locking with Dean-authorized maker-checker waivers ensures strict audit defensibility.

4 Mandatory AI Usage Report (Section 28 Compliance)

In strict compliance with Page 6 of the Pre-Drive Assignment Brief, here is the unvarnished report of AI tool utilization, prompts, modifications, and validation:

AI Tool Used:
Claude (Anthropic) & ChatGPT (GPT-4o)
What I Asked AI to Do:
1. Brainstorm relational schema links connecting the 5 domains into an integrated enterprise ERP.
2. Scaffold boilerplate Next.js App Router API route handlers and initial Tailwind layouts.
3. Draft an initial recursive backtracking skeleton for academic timetable scheduling.
4. Generate realistic synthetic institutional seed data (courses, subjects, faculty, and bank CSV lines).
Prompt That Was Most Useful:
"Implement a pure TypeScript Constraint Satisfaction Problem (CSP) solver using backtracking and forward checking for college timetable scheduling. Hard constraints must include no professor double-booking, no classroom double-booking, room capacity >= class size, and lab subjects in lab rooms. If the constraints are mathematically impossible, do not return an invalid or partial timetable—instead, output a structured conflict diagnostic report detailing the bottleneck and concrete remediation steps."
Code Generated by AI (What part?):
Initial Prisma schema draft for entity definitions, recursive timetable solver skeleton, initial TypeScript interfaces for bank settlement records, and UI layout components.
Code I Modified & Engineered Manually:
• Enforced Exact Integer Minor Units: Replaced all floating-point numbers with integer cents/paise across the schema, seed scripts, APIs, and UI to eliminate float drift.
• Atomic Transactions: Re-wrote fee processing using prisma.$transaction() to guarantee that payments, head distributions, invoice balances, and receipts update atomically.
• Pessimistic Date-Locking: Implemented backend HTTP 423 Locked guards, replacing AI's naive client-side disabled buttons.
• Evaluator 1-Click Role Switcher: Built the client-side session context allowing instant persona switching without credential re-entry.
AI Output That Was Wrong or Sub-Optimal:
In the initial timetable generator, the AI produced a naive recursive solver that used Math.random() to shuffle subjects and periods without pre-solve domain validation or forward checking sets. When tested with realistic constraints (such as 100 students in 60-seat rooms, or high lab hours with limited lab rooms), the solver entered deep recursive loops, frequently exceeded the call stack, or returned incomplete schedules with overlapping faculty slots.
How I Identified the Problem:
I wrote automated unit tests in Vitest (tests/timetable-csp.test.ts) covering tight room constraints and impossible hour requests. The test suite timed out with unhandled call stack overflows instead of failing gracefully.
How I Fixed It:
1. Discarded the random-shuffle approach and implemented formal Minimum Remaining Values (MRV) heuristic sorting (scheduling lab subjects and high-hour core subjects first).
2. Added an instantaneous Pre-Solve Feasibility Check that halts in <5ms with structured diagnostics if requested hours exceed available periods.
3. Introduced deterministic tracking sets (facultyBusy, roomBusy, divisionGrid) to evaluate hard constraints in O(1) time during the search.
